# 근태관리 기능 인수인계 문서

사내 통합관리시스템에 **근태관리 기능**을 추가하기 위해 개발사에 전달하는 문서 묶음입니다.
현재 별도로 동작하는 프로토타입 앱(Next.js + PostgreSQL)에 구현된 기능을 기준으로 작성되었습니다.

## 문서 구성

| 문서 | 내용 | 주 사용자 |
|---|---|---|
| [PRD.md](PRD.md) | 기능 요구사항, 업무 규칙, 권한 정책, 비기능 요구사항 | 기획 / PM |
| [DATA-MODEL.md](DATA-MODEL.md) | 테이블 정의, 관계도, 코드값 정의 | DBA / 백엔드 |
| [API-SPEC.md](API-SPEC.md) | 엔드포인트별 요청·응답·권한·검증 규칙 | 백엔드 |
| [SCREENS.md](SCREENS.md) | 화면 목록, 화면별 구성요소와 동작 | 퍼블리셔 / 프론트엔드 |
| [BUSINESS-RULES.md](BUSINESS-RULES.md) | 상태 전이, 계산식, 차감 규칙 등 핵심 로직 | 백엔드 / QA |
| [INTEGRATION-NOTES.md](INTEGRATION-NOTES.md) | 통합 시 반드시 바꿔야 할 것, 알려진 제약, 미구현 항목 | 아키텍트 / PM |
| [TEST-SCENARIOS.md](TEST-SCENARIOS.md) | 인수 테스트 시나리오 (합격 기준) | QA / 발주처 |

## 읽는 순서 (권장)

1. **PRD.md** — 무엇을 만드는지 전체 파악
2. **INTEGRATION-NOTES.md** — 그대로 가져가면 안 되는 부분을 먼저 확인 (특히 인증)
3. **DATA-MODEL.md** → **BUSINESS-RULES.md** — 데이터와 로직
4. **SCREENS.md** / **API-SPEC.md** — 구현 상세
5. **TEST-SCENARIOS.md** — 검수 기준 합의

## 이 문서의 성격

- 프로토타입은 **기능 검증용**이며, 그대로 이식하는 것을 전제로 하지 않습니다.
- 특히 **인증/계정 관리는 통합관리시스템의 것을 사용해야 합니다.** 프로토타입의 로그인 방식은 테스트 편의용이며 운영에 부적합합니다 ([INTEGRATION-NOTES.md](INTEGRATION-NOTES.md) 참고).
- API 명세는 "이대로 만들라"는 뜻이 아니라 **동작 계약(어떤 입력에 어떤 결과·검증이 필요한가)** 을 전달하는 용도입니다.

## 기능 한눈에 보기

**신청/결재 대상 5종** — 모두 `대기 → 승인/반려` 결재 흐름을 가집니다.

| 구분 | 신청 단위 | 부여(한도) 관리 | 결과보고 |
|---|---|---|---|
| 휴가 | 기간(시작~종료) + 사용일수 | 연도별 · 휴가종류별 일수 | — |
| 시간외근무 | 날짜 + 시작~종료 시각 | **월별** 시간 | — |
| 근무시간 조정 | 적용일 + 변경 희망 시간대 | — | — |
| 교육 | 기간(시작~종료) | — | 있음 |
| 출장 | 기간(시작~종료) | — | 있음 |

**조회 기능**
- 대시보드: 잔여 휴가·시간외근무 현황 카드, 최근 신청 내역
- 달력: 월 단위로 위 5종을 한 화면에서 확인, 날짜 클릭 시 해당일 상세
- 관리자: 전체 직원 근태 현황, 시간대별 근무 현황

**관리자 기능**
- 결재함(5종 승인/반려), 교육·출장 결과보고 열람
- 직원 계정 관리, 휴가 종류 설정
- **일괄 부여**: 연도별 휴가 일수, 연도별 월 시간외근무 시간
